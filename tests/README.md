# 测试

双击 `main.bat`：构建 Release / Win32，依次运行自动测试，列出人工检查，最后暂停。
游戏目录只需修改 BAT 开头的 `GAME_DIR`。不要同时运行多个测试实例。

```bat
tests\main.bat
tests\main.bat unit
tests\main.bat in_game
tests\main.bat in_editor
tests\main.bat list
tests\main.bat unit "Document.*"
tests\main.bat in_editor "Host.QOpensQuestEditor"
```

第二个参数支持 `*`、`?`，匹配 `Suite.Case`；没有匹配用例时返回失败。
列出用例不会启动游戏、部署文件或创建测试数据，但 BAT 仍先构建以保证列表准确。
无人值守运行可使用 `cmd /c "tests\main.bat < nul"` 跳过最后的按键等待。

## 目录与职责

| 目录 | 内容 |
|---|---|
| `unit/` | 公共接口上的解析、编码、编辑状态、保存备份、路径选择及日志协议测试 |
| `in_game/` | 真实游戏启动、LGC 结果读取及 GoogleTest 断言 |
| `in_editor/` | DLL ABI、真实控件交互、真实 MapEditor 宿主入口、人工检查 |
| `common/` | 入口、逐用例报告、隔离目录、进程生命周期、窗口隐藏、配置恢复 |
| `assets/config/` | 共用启动 CFG |
| `assets/unit/` | 固定模拟输入；小输入仍可以直接写在用例中 |
| `assets/in_game/` | 默认执行的 LGC 脚本 |
| `third_party/` | 固定版本 GoogleTest 源码与许可证，构建时无需联网 |

旧实验脚本已删除，不再出现在默认用例或覆盖范围中。

## 断言与结果

使用 GoogleTest 的命名用例和 `ASSERT_*` / `EXPECT_*`。
断言失败显示代码位置及说明；整组退出码不再替代逐用例报告。
一个用例可以包含多个相关断言；1500 次固定种子的随机字节往返是一个用例。
生成的中俄文样本是模拟数据，不表示已验证四个真实游戏版本。

- 绿色 `PASS`：该自动用例通过。
- 红色 `FAIL`：断言、前置条件、启动或超时失败。
- 黄色 `NEED MANUAL`：明确的人工检查，不计为自动通过。
- 自动项意外跳过也会使整体失败。

失败的独立用例不阻止其余用例；工作进程崩溃或超时会使该组失败，随后继续其他组。
退出码 0 仅表示选中的自动项通过，不代表人工项已经完成。

`out/test/run.log` 保存本轮逐项报告；`out/test/latest.txt` 指向本轮工作目录。
工作目录包含各组 GoogleTest XML、汇总、模拟数据及本轮 LGC 日志。
源资源不写入测试结果。EXE/DLL 在 `bin/Win32/Release/`，编译中间文件在 `out/`。

## 自动覆盖

- unit：CFG 字节保真、字段/条件编辑、任务编号、文本编码与无损编辑、mission 文本、
  撤销重做、连接方向、任务/行边界、布局、保存冲突、事务回滚、备份轮换、多语言。
- in_game：读取任务配置、第一任务组、重置状态、开始任务命令、读取任务正文，
  以及任务开始时实际给予和移除背包中的炸药。
- in_editor 独立测试：固定导出、选择通知、窗口生命周期、语言、编码菜单、连线、
  属性页、奖励物品筛选与粘贴、创建删除、撤销、保存/取消和错误处理。
- in_editor 宿主测试：Q、两个 Quest 指令各自的选择及取消、命令入口重开。
  指令测试使用原 MapEditor 的 Find at stack 参数框；对象属性外层插入入口仍需人工验证。

每个独立控件用例都从新的 DLL 副本、配置和模拟数据启动。
宿主用例各自启动 MapEditor，并先通过公开编辑器入口完成初始化握手，再执行目标操作。
这避免将 `WaitForInputIdle` 误当成引擎资源已全部加载。
游戏七项检查共享一次引擎启动；日志必须完整、具名、无重复且汇总一致，才逐项判定。

## 游戏目录和恢复

无需手动打开游戏，也不复制整套游戏。启动前须关闭指定目录中的游戏和编辑器。
新构建的 EXE/DLL 与语言文件直接部署至该目录，已有 QuestEditor 语言配置保留。

测试临时替换启动 CFG、任务配置和首关 LGC，结束后恢复原字节。
注册表使用 `HKCU\SOFTWARE\QuestEditorRE\Tests\Run-<PID>`，强制窗口模式，
不修改玩家原有全屏选项，结束后删除本次测试项。
恢复备份固定在 `out/test/recovery/`；若强杀或断电留下 `.original`，测试会拒绝覆盖，
请先按原文件名恢复，再重新运行。

控件测试使用不切换显示的独立桌面，预期 MessageBox 由测试模拟应答。
游戏和 MapEditor 的旧 Direct3D 不支持此桌面模式，使用正常桌面的屏幕外窗口，
并限制激活。它不是引擎原生 headless；是否瞬间闪窗、抢焦点仍列为人工项。
测试只控制自己启动的进程，不关闭用户的其他程序。

当前真实游戏场景针对 AS2R，需要任务 `1_1_3`、`1_1_4`；测试临时将这两个任务
设为给予和移除炸药，其他任务保持原样。宿主选择需要 `1_1_1`，
并使用已有 `new.map`。其他版本不能直接套用这些编号。
任务状态测试会调用游戏作弊接口；引擎自己的日志/存档行为不等于只读测试。
